# DrCom Rust v1.0.3

修复多个网卡环境下仅按路由或有线优先选择，导致认证无法完成的问题。

- 登录和自动重连时枚举可用的物理网卡，覆盖同一网卡的多个有效 IPv4 地址。
- 优先尝试上次成功登录的网卡，其余按认证服务器路由、网关及连接类型排序。
- 在实际认证端口绑定源 IPv4 和出接口；先进行不带账号密码的挑战请求。核对回复的服务器地址、端口、序号与 nonce，验证通过后在同一个 socket 上登录、保活。
- 网卡不可达或挑战超时会尝试下一候选；挑战通过但登录持续无响应也会切换候选。服务器拒绝挑战或账号密码时终止，避免反复提交凭据。
- 成功登录后将网卡 GUID 原子保存到 `%LOCALAPPDATA%\DrComCampusRust\adapter.json`，不保存 IP 或接口索引。DHCP 地址或索引变化后按 GUID 重新匹配，首选失效后再自动探测，新的网卡登录成功后更新记录。原加密账号设置和开机启动设置保留。
- 手动指定 `local_ip` / `--local-ip` 的配置仍保持固定地址；MAC 覆盖仍有效。探测可以取消。
- 包含此前本地版本的 Windows 浅色/暗色主题跟随与可读性改进。

验证：100 项 Rust 测试，包含网卡超时切换、拒绝后停止、挑战来源端口校验、取消探测、稳定 GUID 优先、验证后的 IP/MAC 报文构造与 socket 复用。开发机实测：真实有线接口收到有效挑战，两个临时虚拟接口及三个已有虚拟接口均不可达；临时网络已移除。该测试未覆盖所有校园网部署和多个真实有线接口同时接入的情况。

程序运行无需管理员权限，不安装驱动。安装器更新现有 Rust 安装目录时需要管理员权限；更新会短暂结束旧客户端。
